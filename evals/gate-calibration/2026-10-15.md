# Gate calibration, October 15, 2026

This is a dated measurement of deterministic findings in the human-control
corpus, using detector and manifest revision
[`2dc826f7b9aea762f5557e56ba88a3e515bd2fed`](https://github.com/conorbronsdon/avoid-ai-writing/tree/2dc826f7b9aea762f5557e56ba88a3e515bd2fed).
The [machine-readable receipt](2026-10-15.json) binds the manifest hash, settings,
aggregate counts, per-register counts and actual CLI cross-check.

All 38 source hashes matched the manifest. All 376 human documents were scored;
none exceeded the detector's length limit or triggered its unsupported-script
exit. Dataset sources contribute individual human rows; machine rows are
excluded. The settings were `technical` context and `rendered-markdown` source
mode, matching the shipped gate defaults.

| Maximum findings allowed per file | Human documents rejected | Rejection rate |
|---|---:|---:|
| 0 | 100 / 376 | 26.6% |
| 6 | 5 / 376 | 1.3% |

The direct detector API and the actual gate CLI agreed on every document's
finding count at both thresholds. CLI checks ran in 19 batches of at most 20
documents per threshold, and each exit code agreed with its rejected-file count.
This measures `issues.length > threshold`, not the composite detector score.

The default remains six findings per file. These results do not establish
AI-authorship accuracy or a suitable threshold for every writing context. The
corpus has uneven register coverage and predates current model generations.

## Register limits

The receipt reports the nearest-rank 95th percentile: sort the finding counts
and select position `ceil(0.95 * n)`, with positions starting at one. Six is at
or above that observed percentile in every represented register in this sample.
The `technical-blog` register has only one document, so its percentile is that
document's count and cannot establish a population threshold.

## Reproduce

Use the pinned revision above, then run `npm run corpus:fetch` and
`npm run corpus:verify`. Stop if a source is missing or its recorded hash differs;
do not silently skip inputs or replace hashes. The measurement used Node
22.23.2. Run this Node script from the repo to reproduce the aggregate and
per-register counts and percentiles:

```js
const {readManifest, loadText, rowsFromText, sha256} = require('./scripts/corpus.js');
const detector = require('./detector/patterns.js');
const counts = [];
const registers = {};
for (const doc of readManifest().documents) {
  const text = loadText(doc);
  if (text === null || sha256(text) !== doc.sha256) throw new Error(doc.id);
  for (const row of rowsFromText(doc, text)) {
    if (row.class !== 'human') continue;
    const result = detector.analyzeText(row.text, {
      contextMode: 'technical', sourceMode: 'rendered-markdown'
    });
    if (result.tooLong || result.unsupportedScript) throw new Error(row.id);
    counts.push(result.issues.length);
    (registers[row.register] ??= []).push(result.issues.length);
  }
}
const summarize = values => ({documents: values.length,
  rejectedAt0: values.filter(n => n > 0).length,
  rejectedAt6: values.filter(n => n > 6).length,
  p95: [...values].sort((a, b) => a - b)[Math.ceil(0.95 * values.length) - 1]});
console.log(summarize(counts));
// Aggregate: 376 documents, 100 rejected at 0, 5 rejected at 6, plus p95.
console.log(Object.fromEntries(Object.entries(registers)
  .map(([name, values]) => [name, summarize(values)])));
// Register results, including p95, must match the receipt's by_register values.
```
