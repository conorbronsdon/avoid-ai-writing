# Judgment and residual-reporting repair follow-up

**Keep #404 draft.** This is a development repair check with one inherited
editor family, one batched response per condition and model-only assessments.
It does not complete #206's final-source two-family editing gate or replace
#322's historical 14/16 report.

## Frozen inputs and source

The [method](method-frozen.json), [inputs](inputs.json),
[review expectations](expectations.json) and complete [source snapshots](sources.json)
were committed before the writing requests. Twelve synthetic inputs were
authored by a fresh agent without repository access or knowledge of the suspected
failures. Four known repair inputs retain their original source and requests.
These are development probes, not a new held-out benchmark. Local source commit
IDs identify the development checkouts; the exact texts and SHA-256 hashes make
them available without depending on those local commit objects.

Both arms include current main through #406, with the same entrypoint, full
loading, context profiles and output contract. Arm A is the pre-repair card
policy. Arm B explicitly preserves an unexplained subjective ranking and reports
the missing scope of retained vague claims. The production release remains
v3.38.0; the pilot and this repair are Unreleased. Published release notes were
restored to main's exact text when integrating that release.

Two fresh writers saw only their skill sources and the 16 raw requests. Each
saved all sixteen complete responses: [A](A-responses.json), [B](B-responses.json).
The editing-task detector, marks, mechanical-preservation and rendered-view tools
were unavailable. Responses disclose model-only assessment. File tools only read
the supplied artifacts and saved answers; there is no instrumented source-file
editing or private-pass trace. Exact model ID, effective settings and per-call
usage were not exposed, and no independent editor family was available.

## Assessments and limitations

A third fresh agent assessed shuffled alternatives against the raw requests and
source. It saw neither policy sources, arm identities, expected answers nor prior
conclusions. The [blind review](blind-review.json) and [key](blind-key.json) retain
its assessments. Counts can overlap and are model judgments, not accuracy rates:

| Arm | Preservation | Unnecessary edit | Missed justified edit | Reporting |
|---|---:|---:|---:|---:|
| A, pre-repair | 0 | 0 | 1 | 0 |
| B, repair | 0 | 0 | 0 | 0 |

Both arms preserved the “most interesting” ranking in this run. That differs
from the earlier failed runs and demonstrates variability, not a causal gain
from this repair. Both retain trust and all-but-one coverage claims. Arm B
retains the positive assessment and unresolved challenge claim while reporting
their missing basis/scope. No general improvement follows from sixteen tasks
or a lower aggregate flag count.

The primary assessment disagrees with one unflagged reporting result: A says
“Residuals: None found” for the broad concession, although the challenge scope
remains unspecified. B explicitly notes the missing scope. The independent
review left A unflagged; its raw record and counts above are retained rather
than silently changed. This disagreement is an additional limit on adjudication.
The review's missed tightening opportunity on A's developer-guide request is
also a model assessment, not a reader-preference measurement.

Tests check receipt completeness, source/input hashes and the recorded exact
scope invariants. They do not implement semantic grading or establish that a
future paraphrase must match these words. The original 96 responses and both
earlier reviews remain intact. Final-source cross-family execution and
independent-family adjudication are still required before acceptance. Any
later editorial change requires rerunning affected scenarios; do not relabel
these responses as evaluation of a future tree.
